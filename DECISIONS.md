# DECISIONS (ADR-style)

Format: id · date · decision · why · consequences. Revise by adding a new entry that supersedes.

- **D001 · 2026-09-09 · Three-layer taxonomy.** Layer A design axes (representation, objective,
  architecture, conditioning & control, training signal, inference); Layer B sections (generation,
  rae, editing, unified, vfm, vlm, medical); Layer C evolution (transitions, open problems, timeline
  graph). *Why:* the user's flat list mixed design choices with capabilities and history; training
  signal and inference were missing yet explain much of 2024–26 progress. *Consequence:* every entity
  carries `axes` and `sections`; transitions and problems are first-class entities.
- **D002 · 2026-09-09 · Stack: Astro 5 + MDX + KaTeX + Pagefind + D3 island + plain CSS tokens;
  GitHub Pages.** *Why:* static, typed content collections, small JS, easy deploy. Rejected Next.js,
  Docusaurus, Hugo, Quarto (see blueprint §5).
- **D003 · 2026-09-09 · Structured data = one YAML file per entity under `data/`, JSON Schema in
  `schema/`, compiled to `graph.json` at build; long-form in `content/**/*.mdx`.** *Why:* queryable by
  site and pipeline; diffable in PRs; human-editable.
- **D004 · 2026-09-09 · No explanatory claim without a fetched source.** Entries are
  `verified: false` until abstract/PDF fetched and read in-session; landmark/core explanations
  require the PDF. *Why:* model knowledge has a cutoff and hallucination risk; this is a research
  reference.
- **D005 · 2026-09-09 · Images only.** Video/3D/audio appear only as pointer nodes.
- **D006 · 2026-09-09 · Pipeline never auto-merges.** Candidates land as YAML + PR; a human or a
  Fable review session verifies. Provisional tier from automation is capped at strong-followup.
- **D007 · 2026-09-09 · Model policy.** Fable 5.1 (Opus 5 as cheaper substitute) for synthesis,
  taxonomy, conflict resolution, landmark reviews; Sonnet 5 for code and drafting; Haiku 4.5 for
  metadata and pipeline filters; deterministic scripts for fetch/dedup/validate/build/deploy.
- **D008 · 2026-09-09 · GANs, early VAEs, DDPM-era diffusion, and pre-2023 editing are background
  concept pages only**, linked from modern pages, never expanded.
- **D009 · 2026-09-09 · Tiers.** landmark = origin of an axis option or changed a family's
  direction; core = required to understand a branch today; strong-followup = meaningful improvement
  inside a branch; emerging = <12 months, promising, unproven; watchlist = closed systems or
  uncertain relevance, metadata only.
- **D010 · 2026-09-09 · Sprint 1 runs on Sonnet 5.** Fable is used in Sprint 1 only for reading
  the RAE follow-ups, LLaDA-Image, and the 2026 frontier recon. *Why:* credit conservation per the
  user's request.
- **D011 · 2026-09-09 · Track current Astro major, not a pinned "Astro 5".** The blueprint's "Astro
  5" was a forward guess written before release; by build time Astro was at 7.3. Used `astro@^7.3`,
  `@astrojs/mdx@^8`. *Why:* the design intent (static, typed content collections, MDX, islands) is
  what D002 actually specified — pinning an outdated major would fight the toolchain for no reason.
  Astro 7 also renamed `src/content/config.ts` to `src/content.config.ts` (legacy content-config
  error otherwise).
- **D012 · 2026-09-09 · Sprint 1 seed set: 30 papers, 23 concepts, 7 problems, 2 transitions, 1
  path, 54 relations.** Generation backbone (10: LDM, DiT, Flow Matching, Rectified Flow, SiT, SD3,
  VAR, MAR, JiT, plus FLUX as a `system` entity since it has no single arXiv paper) + full RAE spine
  from blueprint.md §4.2 (20, compressing some table rows — e.g. Emu/Emu2 — into one entity where the
  table itself treats them as one tier/line). Every paper's arXiv id was fetched and title-matched via
  `scripts/verify_paper.py` before `status.verified` was set true (D004); two transcription errors
  (an em-dash in the BLIP3-o title, a misremembered VA-VAE co-author) were caught this way and fixed.
  All 30 papers are metadata-verified; none have a full-PDF-read `explanation` MDX yet except the one
  transition narrative written for `pixels-to-representation-latents` (P2 writes the rest).
- **D013 · 2026-09-09 · Graph JSON is generated, not committed.** `site/src/data/graph.json` (build-
  time import) and `site/public/graph.json` (client-side fetch for `/graph`) are both gitignored and
  regenerated by `scripts/build_graph.py`, wired as an npm `predev`/`prebuild` hook so `npm run dev`
  and `npm run build` always regenerate from `data/` first. *Why:* avoids a generated artifact
  drifting from its source of truth; a fresh clone still builds correctly with one command.
- **D014 · 2026-09-09 · `/papers/[id]` is one dynamic route, not a single hardcoded `rae-2025` page.**
  Renders all 30 seeded papers from graph data, with tier-conditional detail (full template affordances
  for landmark/core, a short-form notice for strong-followup/emerging/watchlist) per blueprint.md's own
  template-tiering rule. *Why:* a single hardcoded page would leave every other paper link (from the
  transition page, the graph, the homepage) pointing at a 404; the dynamic route was barely more code
  and is what the blueprint's tiering rule was already describing.
